# Crystal Front / LPA: совместная приёмка, 3 октября 2026

## Итог и границы

Публичные страницы LPA и сборка Crystal Front 0.1.34 совместимы в проверенном контролируемом сценарии: настоящий опубликованный HTML/JS обеих сторон, **подставные Auth и RPC** в отдельном чистом Chromium. Это не проверка Google/OTP, записи в production или установленной PWA. Обращения к настоящему Supabase в этом браузере заблокированы; тест не создавал аккаунты, результаты или деньги.

В штатном доступном In-app Browser исходно не было вкладок/доступной авторизованной сессии. Настоящая страница `/games/crystal-front/` открылась; Play перевёл на `/#profile`, где видны Google и вход по коду на почту. Гостевой запуск не произошёл. Вкладка оставлена для входа владельца. Cookies, токены и скрытые профили браузеров не извлекались, письма не отправлялись.

**Блокер настоящей сквозной приёмки:** войти в LPA в доступной этому чату браузерной вкладке. Вход в Supabase или на телефоне не создаёт сессию сайта в этой вкладке. После входа нужны контролируемый матч/выход с согласием и новый read-only снимок БД.

## Controlled integration: опубликованные host + game

Один headless Chromium, viewport 844×430, чистое временное хранилище. Никакие игровые исходники не подменены. Только CDN Supabase factory заменён явно тестовым Auth/RPC, service workers отключены для проверки актуальных опубликованных байтов. Это НЕ тест обновления существующего service worker.

| Сценарий | Наблюдение |
|---|---|
| Реальный player/account handshake | Игра получила ready, открыла ввод ника и записала тестовый профиль |
| Exit из меню | Кнопка игры закрыла официальный iframe |
| Повторное открытие | Namespace прежний, сохранённый профиль открывается без повторного ввода ника |
| Смена A→B | Старый iframe удалён; у B другой namespace и новый профиль |
| Возврат B→A | Вернулся прежний namespace и сохранённый профиль A |
| Начало матча и явный Close | Один match_start и один match_end(outcome=abandon); при повторных открытиях второй результат не появился |
| Активное время | Heartbeat дошёл до тестового RPC: active_time(seconds=15) |
| Согласие выключено | Контекст и Exit работают, новые игровые telemetry RPC отсутствуют |
| Внешние controls | Fullscreen/Close сохранены; playerExit=false не изменён |
| Landscape | Поле и кнопки помещаются в 844×430; это desktop Chromium viewport, не физический телефон |
| JavaScript | pageerror отсутствуют |

Диагностические локальные артефакты (не production player data): `output/crystal-live/report.json`, `menu.png`, `battle.png`. Синтетические actor UUID и значения тестового ника не являются реальными игроками. Полный конкурентный A→B→A с задержанными async ответами проверен прежними контрактными тестами; эта новая live-build проверка подтверждает последовательное переключение реальных опубликованных страниц, не заменяет их.

При смене Auth старая очередь статистики отменяется, чтобы не отправить результаты под новым actor. Конец старого матча при таком переключении не гарантируется; для проверки окончания использован явный Close **до** смены аккаунта. Нельзя ослаблять identity fence ради доставки старого результата.

## Настоящая БД и коммерческие ограничения

[Read-only аудит БД](../supabase/CRYSTAL_FRONT_LIVE_ACCEPTANCE_2026-10-03.md) фиксирует состояние до действий владельца: 2 Crystal Front sessions, из них 1 авторизованная; 1 match_start, 0 match_end. В БД нет build/version, поэтому эти строки нельзя однозначно приписать 0.1.34. Новых событий во время аудита не появилось. Отсутствие end без подтверждённого завершения матча не объявляется дефектом.

Экономика выключена, реальные покупки и rewarded credits отсутствуют. Cloud save/revision/consume — будущий этап B. Старый crystalFrontProgressV1 не мигрировали и не присваивали аккаунту. Сохранение текущей игры не обещает восстановление всей доски активного матча.

Остаётся проверить: настоящий Google/OTP, реальные записи end/active_time, установленную PWA и её обновление, физические Android/iOS/Safari, native visibility/BFCache. Права ElevenLabs этим тестом не подтверждались. playerExit разрешается переключить только после согласованной настоящей приёмки.
