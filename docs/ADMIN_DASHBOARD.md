# Отдельный кабинет владельца LPA

Дата: 2026-10-03. Отдельный read-only кабинет выпускается по адресу https://libertypandaa.github.io/liberty-panda-arcade/admin/; новые RPC применены и проверены в production. Проверка существующего admin через SQL role/claim вернула 2 сессии, 1 завершённый матч и 128 секунд активности за 3 октября UTC. Это не проверка настоящего браузерного входа владельца.

## Адрес и границы

`/liberty-panda-arcade/admin/` — самостоятельная страница. Главная, профиль игрока и игровые оболочки не получают переключатель администратора, ссылку по email или дополнительные права. Владелец на обычном сайте остаётся игроком.

Вход используется обычный: Google или код на почту через существующие `auth.js` / `auth-email.js`. После входа пользователь явно нажимает **Открыть кабинет**. Это действие интерфейса, не авторизация. **Закрыть кабинет** очищает отчёт, сохраняя вход игрока; **Выйти из аккаунта** завершает общую локальную сессию.

Авторизация — только серверная membership-проверка. Email, `user_metadata`, `app_metadata`, localStorage и query string не дают прав. В странице только публичный Supabase config; service key отсутствует. Страница не отправляет игровую телеметрию, не хранит и не кеширует ответы кабинета.

## Точный серверный контракт

Источник истины: [ADMIN_CONTRACT.md](../supabase/ADMIN_CONTRACT.md) в репозитории (путь относительно этого документа). При публикации только `docs/` этот SQL-контракт доступен в GitHub, не как публичный файл сайта.

- `lpa_admin_access()` → `contractVersion: 1`, `access.allowed: true`.
- `lpa_admin_analytics({p_game_id, p_date_from, p_date_to})` → contract v1 с `access`, `summary`, `activity`, `results`, `versions`, `games`, `generatedAt`.
- Даты ISO, UTC inclusive, максимум 31 день. Начальное окно — последние 7 календарных дней UTC. `p_game_id: null` выбирает все зарегистрированные игры.
- Access вызывается перед каждым отчётом. Сам aggregate RPC обязан повторно проверять membership; ответ первого RPC не является capability/token.
- `42501` → «Нет доступа». Missing RPC, сеть или неизвестный формат → «Сервер кабинета недоступен», без fallback к старым RPC и без синтетических данных.
- Поздние ответы после смены аккаунта, A→B→A, закрытия, logout, offline или нового запроса игнорируются. Старые строки удаляются перед новым чтением и при отзыве доступа.

## Что показывает первая версия

Обезличенные агрегаты: игроки за период, сессии, активное время, матчи с результатом, завершения без abandon, победы; дневная активность отдельно по каждой игре; средние результаты с собственными единицами; ошибки; версии/build ID запущенных игр. Смешанных средних points/ms нет. `0` означает известный ноль, `null` — «Нет данных» / «Неизвестно».

Старым сессиям не присваивается текущая версия. Список установленных приложений неизвестен. Сведения относятся к полученным событиям, не всем действиям людей; офлайн/согласие ограничивают полноту. Результаты — клиентская аналитика, не серверно доказанный рейтинг и не основание наград.

Денежных действий, выдачи валюты, изменения прогресса, пользовательских email/UUID, сырых saves или токенов в отчёте нет.

## Что ещё обязательно проверить до объявления работающим

1. Выполнено: новые RPC применены после DB review; production ACL проверки проходят. См. ../supabase/ADMIN_DEPLOYMENT_2026-10-03.md.
2. Read-only сопоставление существующего member с подтверждённым auth user и ранее опубликованным контактом владельца совпало. Новые права не назначались. Это не заменяет настоящий вход владельца.
3. Настоящий разрешённый вход на `/admin/`, Google redirect allowlist и реальный read-only ответ. Пока это не подтверждено, не объявлять кабинет доступным владельцу.
4. Публичный игрок по-прежнему не получает administrative controls.

Код: `docs/admin/index.html`, `admin.css`, `admin.js`. Общие страницы, игровые исходники и существующие сохранения не изменялись.
