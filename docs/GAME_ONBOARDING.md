# Подключение новой игры

Генератор создаёт отдельные страницу игры, страницу установки, manifest, service worker и добавляет запись в реестр. Каталог использует этот реестр. Исходники и сборку игры генератор не меняет. По умолчанию он только показывает план; публикации и запросов к базе нет.

## Паспорт игры

Сохрани JSON, например `new-racer.json`:

```json
{
  "gameId": "new-racer",
  "slug": "new-racer",
  "title": "New Racer",
  "studio": "Liberman Games",
  "description": "Краткое описание игры.",
  "url": "https://libertypandaa.github.io/new-racer/",
  "scoreUnit": "points",
  "orientation": "landscape",
  "assets": {
    "cover": "assets/games/new-racer/cover.webp",
    "icon192": "assets/games/new-racer/icon-192.png",
    "icon512": "assets/games/new-racer/icon-512.png",
    "maskable512": "assets/games/new-racer/maskable.png"
  }
}
```

`gameId` — постоянный отдельный идентификатор; `slug` — каталог оболочки (по умолчанию gameId). Допустимы латинские строчные буквы, цифры и одиночные дефисы. `scoreUnit`: points, milliseconds, none. `orientation`: any, landscape, portrait.

Сначала размести графику в `docs/assets/games/<slug>/`. Иконки — PNG соответствующих размеров; maskable должен иметь безопасные поля. Генератор проверяет пути и наличие файлов, но не размеры изображения или права на него. Эти проверки остаются частью приёмки.

URL сборки должен быть HTTPS, с завершающим `/`, без логина, параметров или фрагмента. Разрешённые хосты утверждаются отдельно в `tools/game-hosts.json`. Паспорт игры не может самостоятельно расширить разрешения. Сейчас разрешены собственные сборки на libertypandaa.github.io. Общий origin не изолирует вредоносный код: сторонние игры требуют отдельного решения по безопасности.

## Команды из корня проекта

```sh
node tools/add-game.cjs new-racer.json
node tools/add-game.cjs new-racer.json --write
node --test tests/onboarding.test.cjs
```

Первая команда не записывает файлы. Вторая создаёт `docs/games/<slug>/` и обновляет JSON-блок между `LPA_GAMES_START` / `LPA_GAMES_END` в `docs/game-registry.js`. Этот реестр — источник каталога и разрешённых iframe URL. Новый gameId/каталог не должен существовать. Повторный запуск отказывается перезаписывать игру. Не редактируй реестр вручную одновременно с генерацией; локальный lock защищает параллельные запуски CLI.

В каталоге игры появляются index.html, install/index.html, shell.js, manifest.webmanifest, service-worker.js и registry-entry.json (копия записи для ревью). Относительные id/scope manifest разрешаются в уникальный URL каталога игры. Кэш имеет отдельный префикс; service worker не активируется принудительно и не перезагружает матч. Игра запускается общим HubPlayer с проверкой аккаунта. Кнопка установки также проверяет аккаунт. Системное меню браузера не может быть запрещено сайтом.

## Сервер и приёмка

Новая запись создаётся с `analyticsEnabled: false`: это не заявление о готовой статистике. Агент БД должен зарегистрировать gameId, разрешённые события и правила результатов; только после реальной проверки включается аналитика. Генератор не предоставляет облачные сохранения, платежи, рекламу или защиту клиентского счёта. Их подключают по действующим контрактам платформы.

Перед публикацией проверить реальный вход, запуск из каталога/страницы/ярлыка, отказ fullscreen и Close/Exit, мобильный экран, сохранения после повторного открытия, смену аккаунта, раздельные записи статистики, защиту от повторов и согласие на необязательную аналитику. Установка оболочки не означает офлайн-готовность внешней сборки. Для игры необходимы собственные проверенные кэширование и сохранения.

Далее следовать GAME_PLATFORM_CONTRACT.md и GAME_EXIT_AND_UPDATE_GUIDE.md. Интеграционные проверки с моками не заменяют проверку опубликованного сайта; непроверенные телефоны/Safari и права на ассеты фиксировать как ограничения.
