# Инструкция для чата разработчика игры

## Задача

Игра разрабатывается для Liberty Panda Arcade:
https://libertypandaa.github.io/liberty-panda-arcade/

Студия и хаб — разные бренды. Сайт запускает игру в iframe полноэкранного
плеера. Аккаунт, согласие на статистику и запросы к Supabase обслуживает хаб.
Игра НЕ получает email, токен аккаунта, гостевой секрет или ключи Supabase.
Не создавайте второй аккаунт и не обращайтесь к таблицам статистики напрямую.

Подключите готовый SDK версии протокола 1. Он уже доступен в репозитории
хаба в `docs/game-analytics-sdk.js`. Можно закрепить копию файла в игре.
Адрес опубликованного файла:
https://libertypandaa.github.io/liberty-panda-arcade/game-analytics-sdk.js

Сейчас в хабе и базе зарегистрирована `crystal-front-demo`, источник игры:
https://libertypandaa.github.io/crystal-front-demo/
Другую игру сначала регистрирует разработчик хаба: отдельный game ID,
разрешённый адрес iframe, запись в проверках базы и разрешённые custom-события.
Нельзя переиспользовать ID Crystal Front для другой игры.

## Подключение

Загрузите SDK до основного кода игры. Например, два последовательных defer-скрипта:

```html
<script defer src="https://libertypandaa.github.io/liberty-panda-arcade/game-analytics-sdk.js"></script>
<script defer src="./game.js"></script>
```

В модульной сборке надёжнее включить локальную копию SDK до инициализации
игры. Не блокируйте игру, если SDK недоступен. Не меняйте существующие
правила, баланс, сохранения или рейтинг ради внедрения аналитики.

```js
const analytics = window.LibertyPandaAnalytics;

// Ассеты загружены, главное меню действительно интерактивно.
analytics?.ready();

// Новый матч. Хранить ID до его окончания, не генерировать новый для результата.
const matchId = analytics?.matchStart('duel');
analytics?.setPlaying(true);

// Пауза, меню, реклама, потеря управления игрой.
analytics?.setPlaying(false);

// Продолжение активного геймплея.
analytics?.setPlaying(true);

// Результат отправлять один раз из единого обработчика конца матча.
analytics?.setPlaying(false);
if (matchId) analytics?.matchEnd(matchId, 'win', 120);

analytics?.tutorial('first_duel', 'start');
analytics?.tutorial('first_duel', 'complete');
analytics?.progress('chapter_1', 35);
analytics?.achievement('first_win');
analytics?.error('assets_load_failed');
analytics?.custom('bomb_used', 1);
```

`matchStart` возвращает UUID либо `null`, если отправка выключена. Результат
матча, начало которого не было записано, сервер отклонит. Не восстанавливайте
предыдущие события задним числом после согласия. Начните учёт со следующего матча.
Методы возвращают факт передачи сообщения родителю, НЕ подтверждение сохранения
в базе. Отказ статистики, потеря сети и ошибка сервера не должны ломать игру.

## События и определения

| Метод | Когда вызывать | Что попадает в отчёт |
|---|---|---|
| `ready()` | Игра готова к взаимодействию | Успешная загрузка, среднее и p95 времени загрузки |
| `setPlaying(true/false)` | Начало/пауза активной игры | Активные секунды, среднее время сессии |
| `matchStart(mode)` | Фактическое начало матча | Матчи, режим |
| `matchEnd(id, outcome, score)` | Конец матча | Победы, поражения, ничьи, выходы, доля побед, средний счёт |
| `tutorial(step, state)` | Начало/завершение шага | Количество игроков на каждом шаге обучения |
| `progress(level, percent)` | Значимое изменение прогресса | Средний лучший прогресс игроков по этапу |
| `achievement(id)` | Реальное открытие достижения | Количество открытий и игроков по достижению |
| `error(code)` | Обработанная ошибка игры | Количество по стабильному коду ошибки |
| `custom(name, value)` | Заранее согласованное событие | Количество, сумма и среднее числового значения |

`outcome`: `win`, `loss`, `draw`, `abandon`. `state`: `start`, `complete`.
Идентификаторы: латинские строчные буквы, цифры, `_`, `.`, `-`, до 64 символов.
Процент: 0–100. Счёт и custom-значение: конечное число от -1 000 000 до 1 000 000.
Счёт округляется SDK до целого. Не отправляйте прогресс каждый кадр: только
смена этапа или заметный прогресс, например ещё 10%.

## Собственная статистика игры

Сначала сформулируйте вопрос: например, какие бонусы используют чаще.
Опишите каждое событие: имя, точный момент отправки, единица измерения,
ожидаемая частота, пример и правило предотвращения дублей.
Передайте этот список разработчику хаба. Он добавит имена в серверный allowlist
`public.game_analytics_custom`. Не передавайте произвольные объекты в custom.
Уже разрешены для Crystal Front: `bomb_used`, `line_used`, `color_used`, `shuffle_used`.
Например, `custom('bomb_used', 1)` означает одно использование бомбы.
Новое имя без регистрации не будет сохранено. Добавлять ключи к payload нельзя.

Нельзя отправлять имена, email, чаты, URL с параметрами, токены, IP,
полные тексты ошибок/stack trace или пользовательский текст. Только технические
коды из заранее определённого набора и числовые значения.

## Протокол и безопасность

SDK общается только с `window.parent` через `postMessage`, точный origin:
`https://libertypandaa.github.io`, без `*`. Хаб проверяет origin, source, номер
протокола и случайный ID текущей сессии. Личность берётся из сессии хаба, не из игры.
Хаб отправляет `lpa:config`, SDK — `lpa:hello` и `lpa:event`. Не реализуйте
второй ручной отправитель параллельно SDK; не отправляйте старый `game_ready`.
При отзыве согласия/смене аккаунта старая сессия перестаёт принимать события.

SDK не передаёт учётные данные, но это не изоляция недоверенной игры:
сейчас игра и хаб размещены на одном origin GitHub Pages. Подключать можно
только доверенный код своих игр. Для сторонних игр нужен отдельный origin
и пересмотр разрешений iframe, а не только проверка postMessage.

При прямом открытии игры без iframe SDK молчит: общего аккаунта и согласия
родителя там нет. Установленная оболочка хаба поддерживается, отдельная PWA
самой игры потребует отдельной согласованной интеграции авторизации и согласия.
Прямой переход на GitHub-версию игры сам по себе статистику хаба не включает.

SDK измеряет время только после `setPlaying(true)`, исключая скрытую вкладку.
Пакеты отправляются примерно каждые 15 секунд. Последний непереданный интервал
может потеряться при аварийном закрытии. Сон устройства не считается игровым
временем. Параллельные игровые вкладки считаются отдельными сессиями.

Хаб ограничивает приём 120 сообщений в минуту, очередь — 120 событиями.
Сервер допускает до 4000 игровых событий на идентификатор в сутки и payload
до 512 байт. Дубли одного event ID и результата одного матча не учитываются
повторно. Автоматической надёжной офлайн-доставки и повторов SDK пока нет.
Сессия без закрытия/матч без результата старше 24 ч показаны как незавершённые,
а не как подтверждённый проигрыш.

Это клиентская аналитика, а НЕ античит и НЕ подтверждённый рейтинг.
Для соревновательных очков потребуется проверка результата доверенным сервером.
Достижения здесь — аналитические события, не серверная система выдачи наград.
`progress` — статистика, не облачное сохранение состояния игры.

## Приёмочные тесты разработчика

1. Без согласия игра работает; игровые события не пишутся в Supabase.
2. После согласия и запуска: одна сессия и одна успешная загрузка.
3. Минута активной игры даёт примерно минуту; пауза/скрытая вкладка не добавляют время.
4. Один матч даёт одно начало и один результат; повтор результата не удваивает счёт.
5. Достижение не дублируется при перезагрузке в том же аккаунте.
6. Прогресс и шаги обучения появляются в профиле и отчёте владельца.
7. Разрешённое custom-событие отражается в отчёте, неизвестное отклоняется.
8. Выход из аккаунта/отзыв согласия прекращает старую сессию.
9. Потеря сети, отключённый SDK и запуск напрямую не мешают играть.
10. В сетевых запросах игры нет ключей базы, email или токенов пользователя.

Для проверки запускайте игру через хаб, затем откройте Profile и
Settings → Статистика хаба → Обновить статистику. Не объявляйте интеграцию
готовой только по наличию вызовов в коде: нужны реальные события в отчёте.
