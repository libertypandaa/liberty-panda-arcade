# Как адаптировать игру к Liberty Panda Arcade

Общая инструкция для чата разработчика игры. Актуальность: 20 сентября 2026 года.
Это описание текущей интеграции и требований к новой игре, а не обещание
уже существующих облачных сохранений, рейтингов или универсального API аккаунта.

## 1. Что представляет собой платформа

- Хаб: https://libertypandaa.github.io/liberty-panda-arcade/
- Репозиторий хаба: https://github.com/libertypandaa/liberty-panda-arcade
- Название сайта: **Liberty Panda Arcade**. Не соединяйте его с названием студии в один бренд.
- Студийный сплэш остаётся частью игры. Сохраняйте утверждённые имя и логотип студии.
- Файлы хаба публикуются из `docs/` через GitHub Pages.
- Игры могут публиковаться отдельно. Сейчас Crystal Front загружается с
  https://libertypandaa.github.io/crystal-front-demo/ в iframe хаба.
- Вход Google и профиль обслуживает Supabase. Игры работают и без входа.

Поток: каталог → Play → полноэкранный плеер хаба → iframe игры → главное
меню игры. Сам матч начинается обычным действием игрока. Не нужно заставлять
его переходить на отдельную страницу перед запуском.

## 2. Что уже есть и чего ещё нет

| Возможность | Текущее состояние |
|---|---|
| Каталог, кнопка Play, плеер и закрытие игры | Работают для Crystal Front |
| Установка оболочки игры на телефон | Есть, средствами поддерживаемого браузера |
| Google-вход, профиль хаба | Есть; не означают автоматический вход внутри игры |
| Согласие, гости, статистика хаба | Есть |
| SDK игровых событий и отчёты | Готовы; нужны вызовы SDK в коде каждой игры |
| Облачные сохранения игр | Не реализованы |
| `getPlayer`, `loadProgress`, `saveProgress`, `submitScore` | Не являются доступным API текущего SDK |
| Проверенный общий лидерборд и серверная выдача наград | Не реализованы |
| Универсальная регистрация новой игры одной записью | Пока нет: требуется изменение кода хаба и разрешений базы |

Не выдавайте события `progress` за сохранение игры, а `achievement` за
подтверждённую награду. Не используйте демонстрационные очки как реальные данные.

## 3. Разделение ответственности

**Разработчик игры:** сборка, загрузка, меню, геймплей, управление, звук,
локальные сохранения, события SDK, обработка ошибок, версия игры и её публикация.

**Разработчик хаба:** карточка игры, разрешённый URL, iframe, Play/установка,
оболочка PWA, общий вход, согласие, гостевая идентификация, доступ к базе,
регистрация game ID и собственных событий, отчёты.

Разработчик игры не должен самостоятельно менять продакшен-базу хаба,
Google OAuth или общие политики доступа. Подготовьте запрос на нужное
расширение с перечнем данных и тестами, передайте его в чат хаба.

## 4. Подготовьте паспорт игры

Перед подключением передайте в чат хаба:

```text
Название:
Утверждённое имя студии:
Предлагаемый gameId: (стабильный lowercase-kebab-case, утвердить в хабе)
Репозиторий:
Публичный HTTPS-адрес сборки:
Команда сборки и папка результата:
Версия / commit сборки:
Жанр и короткое описание:
Статус: playable / demo / planned
Устройства и поддерживаемые ориентации:
Управление: мышь / клавиатура / сенсор / gamepad
Обложка, заставка, квадратная иконка:
Локальные сохранения: формат, ключи, версия схемы
Нужен ли интернет для игры:
События статистики и собственные события:
Известные ограничения:
```

`crystal-front-demo` принадлежит Crystal Front. Новая игра не должна
отправлять данные под этим ID. Текущие проверки хаба и базы допускают
только Crystal Front; название новой игры в SDK само по себе её не регистрирует.

## 5. Веб-сборка и пути

1. Сделайте стабильный HTTPS-адрес, открывающий игру, а не репозиторий или страницу скачивания.
2. Настройте базовый путь сборки под её реальный подкаталог GitHub Pages.
3. Проверяйте загрузку ассетов по опубликованному адресу, не только на localhost.
4. Игра должна нормально открываться с дополнительными query-параметрами.
   Сейчас хаб добавляет `?launch=<timestamp>`; это метка запуска, не токен пользователя.
5. Не используйте абсолютные пути вида `/assets/...`, если ассеты лежат в подкаталоге игры.
6. Покажите состояние загрузки и понятную ошибку с повторной попыткой вместо вечного пустого canvas.
7. Не переносите игру на другой движок только ради интеграции. Сначала адаптируйте существующий проект.

Для роутинга учтите прямое открытие URL на статическом хостинге. Не добавляйте
маршруты, требующие серверного rewrite, без проверки публикации.

## 6. Работа внутри iframe

Игра занимает доступную область iframe, а не размеры внешнего экрана устройства.
Обновляйте размер canvas/рендера при resize и смене ориентации; сохраните
пропорции игрового поля и доступность всех кнопок.

Запрещено без согласования:
- перенаправлять `window.top` или открывать обязательную новую вкладку для игры;
- читать DOM, localStorage, сессию или токены родительского хаба;
- заменять его навигацию, перекрывать Close или создавать второй внешний плеер;
- регистрировать service worker с областью действия всего домена.

Если ваш хостинг задаёт `X-Frame-Options` или CSP `frame-ancestors`, убедитесь,
что встраивание в origin `https://libertypandaa.github.io` разрешено.
`frame-ancestors` настраивается HTTP-заголовком, не HTML meta-тегом.
Не отключайте все защитные заголовки ради iframe.
[Описание ограничения CSP](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Content-Security-Policy/frame-ancestors).

Текущий iframe разрешает `fullscreen; autoplay; gamepad`, но разрешение не
гарантирует автоматический звук или fullscreen во всех браузерах. Полный экран
запрашивает хаб; при отказе остаётся плеер на всю страницу. Игра должна работать
в обоих режимах, не требуя повторного обязательного fullscreen.
[Требования Fullscreen API](https://developer.mozilla.org/en-US/docs/Web/API/Element/requestFullscreen).

## 7. Управление, мобильные устройства и пауза

- Поддержите мышь/клавиатуру и сенсор там, где они заявлены в паспорте игры.
- Основные действия не должны зависеть только от hover или правой кнопки мыши.
- Ограничивайте перехват жестов областью игрового поля; не блокируйте весь браузер.
- Проверьте маленький экран, обе заявленные ориентации, экранную клавиатуру и системные отступы.
- Звук запускайте или возобновляйте после взаимодействия игрока; сохраняйте настройку громкости.
- При скрытии вкладки приостанавливайте локальную симуляцию и звук, где это допустимо правилами игры.
- Для сетевого матча не обещайте остановку сервера: отключайте только локальные действия и отображайте состояние связи.
- На возвращении не делайте огромный шаг симуляции за время сна устройства.

Внутриигровая кнопка выхода может вернуть в меню игры. Закрытие плеера
обслуживает кнопка Close хаба. **Сообщение SDK для закрытия плеера пока не
реализовано**, не придумывайте `exit_game` без согласования протокола.

## 8. Сохранения и аккаунт

Сейчас сохраняйте прогресс локально средствами игры. Изолируйте ключи,
например `lpa:<gameId>:save:v1`; храните версию схемы и миграции старых сохранений.
Не вызывайте `localStorage.clear()` и не очищайте общие кэши домена.
Обрабатывайте недоступное хранилище и повреждённые данные без падения игры.

Сохраняйте после значимых действий, а не только на `unload`: хаб закрывает
игру заменой `iframe.src` на `about:blank`. Не полагайтесь на последний
сетевой запрос при закрытии как на гарантированное сохранение.

Google-вход в хаб не даёт игре готовый профиль или облачное сохранение.
Не создавайте второй Google OAuth, не читайте токен из хаба и не встраивайте
service-role/secret key. SDK статистики сам по себе не предоставляет аккаунтный API.
Для будущих облачных сохранений отдельно согласуются методы, RLS, конфликт
двух устройств, гостевой прогресс, схема версий и удаление данных.

## 9. Статистика

Следуйте [отдельной инструкции по игровой статистике](./GAME_ANALYTICS_GUIDE.md).
Файл SDK: [game-analytics-sdk.js](./game-analytics-sdk.js).

Минимальное подключение:
- `ready()` после готовности меню и основных ассетов;
- `setPlaying(true/false)` при начале активной игры, паузе и выходе в меню;
- `matchStart` / `matchEnd`, если игра имеет матчи;
- прогресс, обучение, достижения и технические коды ошибок, если применимы;
- собственные числовые события только после регистрации их имён в хабе.

Сбор добровольный. Игра обязана работать без согласия, без аккаунта,
без SDK и при недоступной аналитике. При прямом запуске вне хаба SDK не собирает
статистику автоматически. Не посылайте email, имя, чат, токены и произвольный текст.

## 10. Установка на телефон

В каталоге относительно игры предусмотрены две основные команды:
**Play** и **Add to phone**. Кнопка установки ведёт сразу к установке,
а не через страницу описания игры. Лишняя кнопка «Original game» не нужна.

Сейчас устанавливается веб-оболочка хаба с manifest и иконкой игры. Её
`start_url` включает `?launch=phone-shortcut`, поэтому при открытии загружается
плеер с игрой. Это не APK и не публикация в магазине.

Разработчик игры передаёт настоящую квадратную иконку (не заглушку), варианты
192×192 и 512×512, а также исходник. Для maskable-варианта оставьте безопасные
поля и отдельно проверьте системное обрезание. Карточке нужны обложка и
заставка без текста, который станет неразборчивым на телефоне.

Manifest, пути установки, `id`, scope и service worker оболочки меняет чат хаба.
Не создавайте конкурирующее предложение установить другую PWA внутри iframe.
Если игре нужна отдельная самостоятельная PWA, это отдельная согласованная задача.

Установка не гарантирует офлайн-работу самой игры: её ассеты и сохранения
должны поддерживать такой режим отдельно. Не объявляйте игру установленной
только потому, что пользователь нажал кнопку. Не требуйте от игры открыть
системное меню браузера программно.

## 11. Обновления и кэш

Изменение кода становится публичным после push и успешной публикации сборки,
а не после одного локального commit. Стабильный адрес игры позволяет хабу
загружать новую опубликованную сборку без повторного добавления карточки.

Версия хаба и версия игры — разные значения. Показывайте версию игры в её
меню/настройках. Желательно предоставить собственный `version.json` с версией
и commit; это требование к новой интеграции, не уже готовая проверка всех игр в хабе.

Ассеты версионируйте именами/хешами. При наличии service worker игры меняйте
его кэш и удаляйте только кэши с префиксом своей игры. Область действия worker
не должна захватывать хаб или соседние проекты.
[Область действия service worker](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Service-Worker-Allowed).

Проверяйте обновление со старой установленной версии, а не только из чистого
браузера. Не перезагружайте матч принудительно ради обновления. Учитывайте,
что нынешняя оболочка хаба может перезагрузиться при активации обновления worker:
регулярные контрольные сохранения нужны уже сейчас; отложенное обновление
оболочки во время матча требует отдельной доработки хаба.

## 12. Доверие и безопасность

Подключаются собственные доверенные игры. Сейчас проекты на одном
`libertypandaa.github.io` имеют общий origin: iframe сам по себе не является
защитой хаба от вредоносного кода игры. Для сторонних игр необходим отдельный
origin и согласованная изоляция.

Не добавляйте рекламные сети, собственные трекеры, платёжные действия или
разрешения камеры/микрофона без отдельного решения владельца. Не считайте
клиентский счёт защищённым от подделки. Проверка source/origin сообщения SDK
не заменяет серверную проверку результатов соревнования.

## 13. Приёмка перед публикацией

| Проверка | Ожидаемый результат |
|---|---|
| Публичный URL, в том числе с `?launch=test` | Нет 404 ассетов и блокирующих ошибок |
| Play с главной и карточки | Сразу плеер, без промежуточной страницы |
| Fullscreen отклонён браузером | Игра остаётся доступной на всю область плеера |
| Закрыть и открыть заново | Нет двойных таймеров/звука; нужный прогресс сохранён |
| Десктоп и реальный телефон | Всё поле и управление доступны, нет перекрытий |
| Скрытая вкладка, возврат, смена ориентации | Корректные пауза, размер и возобновление |
| Гость и аккаунт | Играть можно в обоих случаях |
| Согласие выключено / SDK не загрузился | Игра работает, статистика не требуется |
| Согласие включено | Ожидаемые события в Profile и отчёте владельца |
| Медленная/отсутствующая сеть | Понятная ошибка или заявленный офлайн-режим |
| Ярлык на телефоне | Иконка игры, открытие плеера, нет лишней страницы описания |
| Обновление старой версии | Новый build, сохранения совместимы, чужие данные не очищены |

Записывайте фактические результаты, браузер, устройство и версию сборки.
Непроверенное отмечайте как непроверенное. Не называйте интеграцию завершённой
только потому, что сборка прошла или файл SDK добавлен.

## 14. Готовый запрос для чата разработчика

> Адаптируй нашу игру под Liberty Panda Arcade по этой инструкции и связанному
> GAME_ANALYTICS_GUIDE.md. Сначала изучи проект, сохрани текущие движок,
> правила и прогресс. Подготовь паспорт игры и список изменений в игре и хабе.
> Реализуй корректную iframe-сборку, адаптивное управление, паузу, локальные
> сохранения с версией, загрузку и обработку ошибок. Подключи готовый SDK без
> ключей Supabase и без второй авторизации. Не выдумывай отсутствующий API
> облачных сохранений и рейтинга. Для новой игры запроси регистрацию её ID,
> URL и собственных событий в чате хаба. Выполни приёмочные тесты, затем
> передай URL сборки, commit, ассеты, результаты проверок и оставшиеся ограничения.
