# Контракт подключения игр к платформе LPA

Проект контракта от 30 сентября 2026 года для агентов игр Liberman Games. Это будущая платформа, не список существующих методов SDK. До реализации и проверки хаба не вызывать выдуманные API в production. Продуктовые правила: [техническое задание](PLATFORM_SPEC.md).

## Разделение ответственности

Хаб отвечает за аккаунт, серверные права, реестр релизов, сохранения, принятие ветки, валюту, покупки, рекламу и кабинеты. Игра — за собственное состояние, совместимость схем, управление, локальную запись, остановку/возобновление, отправку событий и адаптер интеграции. Исходники игр меняют их агенты; инструкции сайта не являются изменениями игры.

Игра не получает токены Google/Supabase, email или гостевые секреты через postMessage. Для встраивания использовать посредник оболочки. Для независимой PWA нужен согласованный механизм авторизации SDK, а не копирование токена в URL. Конкретный способ привязки установки определяется на этапе аккаунтов. Все игры на общем origin считаются доверенными; iframe на этом origin не обеспечивает изоляцию от злонамеренной игры. Для сторонних игр пересмотреть размещение и границы доступа.

## Паспорт релиза

Передать gameId, имя студии Liberman Games, приватный репозиторий разработки и публичный URL релиза (если эти роли используются проектом), buildId, sourceCommit, версию SDK, saveSchemaVersion, перечень ресурсов офлайн, возрастную аудиторию, управление/ориентации, графику, правила результатов и наград, товары и ограничения. Метаданные не должны раскрывать секреты или ненужные внутренние материалы.

## Предлагаемые операции платформы

| Операция | Данные и результат |
|---|---|
| Подключение | Версия протокола, gameId, buildId; ответ о возможностях и готовности аккаунта |
| Чтение состояния | Только состояние текущего аккаунта и игры, revision и версия схемы |
| Отправка ветки | submissionId, baseRevision, схема, buildId, snapshot, результаты и расходы; accepted/conflict/invalid/unauthorized |
| Сообщение установки | installationId, buildId, возможности среды и время сервера; не аппаратный отпечаток |
| Проверка релиза | Ответ LPA об одобренном buildId, совместимости и адресе обновления |
| Кошелёк и магазин | Чтение баланса/каталога; запрос покупки productId с idempotency key, цену выбирает сервер |
| Реклама | Запрос предложения/показа, состояние операции; начисление только сервером |
| Выход | Отдельный player-протокол из инструкции по выходу |

Имена методов и wire-schema v2 фиксируются перед реализацией. Нельзя считать приведённую таблицу уже доступным SDK. Текущий analytics v1 сохраняет совместимость, но не является API сохранений, валюты или доказательством принятого результата.

## Обработка сохранений

Локально хранить базовую серверную revision, состояние и неизменяемые отправки до подтверждения. Повторять тот же submissionId с тем же телом после потери ответа. Не присваивать новую облачную revision клиентом и не менять baseRevision отклонённой ветки, чтобы насильно загрузить её повторно.

При конфликте серверная версия заменяет ветку в безопасной точке с уведомлением. Результаты/награды отклонённой ветки не отправлять отдельным обходным путём. Технические события отделены и помечены статусом ветки. Операции кошелька, оплаченные покупки и рекламные награды не затирать снимком игры.

Игра предоставляет валидатор схемы и ограничения допустимых результатов, правила миграции старых сохранений, стабильные ID матчей/достижений и способы сверки расходников. Согласовать учёт grantId, чтобы покупка не выдавалась повторно и не терялась при конфликте. Секретный ключ в браузерном коде не обеспечивает доверенность результатов.

## Транспорт и повторные запросы

Для postMessage проверять точные origin, source, protocol и текущий launchId; значения gameId и прав определяет реестр/сервер. Ошибки аккаунта, синхронизации, загрузки и рекламы не смешивать. Истечение авторизации допускает продолжение локальной игры, но блокирует сетевые расходы до восстановления входа. Очереди старого аккаунта не отправляются под новым.

Вне сети доступны локальная игра и расход локальных бонусов. Онлайн обязательны расходы валюты и подтверждение серверных наград. Фоновая отправка — best effort; обязательны повтор при открытии и устойчивость к дубликатам. Не объявлять режим офлайн готовым без проверки загрузки всех ресурсов и сохранений после закрытия.

## Приёмка агента игры

Проверить опубликованную сборку внутри настоящего LPA и отдельной PWA: вход, смена аккаунта, офлайн, повторное открытие, две ветки от одной revision, потеря ответа, повтор операции, конфликт без двойного рейтинга, сохранность покупки, отказ рекламы, безопасное обновление и Exit. Проверки кошелька выполняются в тестовой среде.

Передать хабу commit/build, матрицу проверок и ошибки. Для реального телефона/Safari указывать фактическое устройство; эмуляцию подписывать отдельно. Удалять внешний Close только после совместной проверки внутреннего Exit и поведения старых сборок. Подробности: [выход и обновления](GAME_EXIT_AND_UPDATE_GUIDE.md).
