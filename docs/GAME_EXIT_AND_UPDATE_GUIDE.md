# Выход из игры и безопасное обновление — подготовка к публикации в LPA

Дата: 29 сентября 2026 года.
Статус на 2 октября: обработчик lpa:player v1 реализован в оболочке и проверен на контролируемом стенде. SDK game-platform-sdk.js готов для включения в сборку игры. Внедрение в реальные игры ещё не подтверждено: для них playerExit=false и внешний Close сохранён. Инструкция SDK: [GAME_SDK.md](GAME_SDK.md).

Эта инструкция — обязательная часть GAME_INTEGRATION_GUIDE.md для новых игр и обновлений интеграции. Агент игры реализует игровую сторону; агент сайта — оболочку. Игровые исходники разрабатываются в репозитории игры, публичный релиз содержит файлы, необходимые для запуска. Хаб использует только разрешённый публичный URL.

## 1. Поведение Exit Game

| Среда | Результат |
|---|---|
| Игра в iframe сайта LPA | Сохранить прогресс, остановить игру и звук, запросить закрытие iframe. Хаб возвращает исходную страницу каталога/игры/установки и выходит из fullscreen. |
| Игра в PWA, установленной через LPA | Тот же протокол и закрытие iframe; остаётся стартовая страница оболочки с Play и переходом в каталог. Не обещать закрытие окна приложения ОС. |
| Прямая ссылка на игру или собственная PWA игры без оболочки LPA | Возврат в главное меню игры; не вызывать произвольное закрытие вкладки. |
| Отдельная нативная Android-оболочка | Отдельный платформенный адаптер выхода, если предусмотрен проектом. Это не PWA и не postMessage-контракт хаба. |

Наличие standalone display НЕ доказывает, что игра запущена в LPA. Определяйте поддержку по проверенному обмену сообщениями, а не по user-agent. window.parent !== window означает только встраивание.

## 2. Согласованный формат предлагаемого протокола v1

Origin хаба в production: https://libertypandaa.github.io
Хаб добавляет к URL игры launch=<UUID> для каждого нового iframe. Это идентификатор запуска, не пользовательский токен и не аналитическая session.

Игра после установки message-listener отправляет hello родителю с точным targetOrigin:

```js
{ type: 'lpa:player:hello', protocol: 1, launchId: '<UUID из URL>' }
```

Хаб после проверки загруженного документа отвечает в его contentWindow с точным origin игры:

```js
{
  type: 'lpa:player:config', protocol: 1,
  launchId: '<тот же UUID>', capabilities: { close: true }
}
```

Чтобы исключить гонку с iframe load, хаб также отправляет config после проверенного load; игра может ограниченно повторить hello до получения config. Не создавать бесконечный цикл сообщений. Если подтверждение не получено, сохранять самостоятельный выход в главное меню и внешний Close хаба.

По нажатию Exit Game, после успешной записи сохраняемого прогресса:

```js
window.parent.postMessage({
  type: 'lpa:player:close',
  protocol: 1,
  launchId, // из URL, подтверждённый config
  requestId: crypto.randomUUID()
}, 'https://libertypandaa.github.io');
```

Один клик — один requestId; повторная доставка того же запроса не должна повторять результаты или закрывать следующий запуск. На время выхода блокировать повторные клики. При неподдерживаемой оболочке возвращаться в меню; не зависать на ожидании ответа. Подтверждение после удаления iframe не гарантируется.

## 3. Проверки сообщений

На стороне игры: event.source === window.parent; event.origin точно равен разрешённому origin хаба; объект ожидаемой формы, type/protocol известны; launchId валиден и совпадает с URL текущего запуска; capabilities.close === true. Не принимать адрес родителя из непроверенного query-параметра. Для локальной разработки использовать отдельный явный allowlist.

На стороне хаба, для hello и close:

- Есть активный запуск и загруженный разрешённый документ.
- event.source === current.frame.contentWindow.
- event.origin === new URL(current.game.url).origin.
- launchId — UUID и равен current.id; type/protocol и форма полей проверены.
- gameId определяется реестром хаба, не сообщением игры.
- Проверены origin, pathname и launch фактического документа iframe, а не только атрибут src. Сейчас общий origin позволяет читать location. При переходе на отдельный origin этот способ недоступен: заранее пересмотреть проверку загрузки/навигации и не отключать её молча.
- requestId корректен; уже закрывающийся запуск и дубликаты игнорируются. Старый iframe не может закрыть новый.
- Никаких URL навигации, исполняемого кода и команд очистки хранилищ в payload.

Одинаковый origin всех GitHub Pages-проектов НЕ различает игры: обязательны source и launch. Доверенные игры на общем origin не изолированы от хаба как от вредоносного кода.

Управление плеером независимо от согласия на аналитику, SDK, Supabase и аккаунта. Не использовать аналитический lpa:config/session вместо этого протокола.

## 4. Последовательность выхода и ответственность

Игра сохраняет постоянный прогресс, дожидается завершения транзакции, останавливает симуляцию/таймеры/звук. При ошибке записи показывает ошибку и выбор повторить сохранение или выйти без него. Не обещать восстановление текущего матча, если оно не реализовано.

Завершённый матч отправляется существующим SDK ровно один раз при доступной аналитике. Exit не создаёт фиктивную победу/поражение. Не задерживать выход ожиданием ответа сервера статистики. Согласовать abandon с уже существующей обработкой закрытия в хабе, не вводить вторую независимую отправку результата.

Хаб обрабатывает close через HubPlayer.close(): hub:playerclosing до уничтожения iframe, завершение текущей аналитической сессии по её правилам, скрытие overlay, выход из fullscreen и возврат фокуса. Закрытие не очищает localStorage/IndexedDB, не выходит из аккаунта и не перезапускает игру автоматически. Автозапуск ярлыка допускается при новом открытии страницы, а не в ответ на close.

## 5. Удаление верхней панели — задача агента сайта

Файлы: docs/game-player.js, docs/game-player.css и пять HTML-страниц:
- docs/index.html
- docs/games/crystal-front/index.html
- docs/games/crystal-front/install/index.html
- docs/games/clutter-cup/index.html
- docs/games/clutter-cup/install/index.html

Удалять панель только после подтверждённого внутреннего выхода для соответствующей игры. Для старых сборок без контракта сохранять резервный Close. При удалении разметки удалить/защитить обращения closeButton.addEventListener; перенести фокус с удалённой кнопки на доступный элемент плеера. Escape — дополнительный путь, но не единственный: клавиатура iframe не всплывает в родителя.

Сохранить requestFullscreen при пользовательском Play и CSS fallback position:fixed/inset:0/100dvh с растянутым iframe. Автостарт PWA может не получить native fullscreen без жеста; режим на всё окно обязателен. Проверить safe-area и доступность Exit в горизонтальной ориентации.

## 6. Версии и обновления

Версия оболочки и версия игры — разные сущности. Обновление LPA не доказывает обновление игры. launch UUID не является номером релиза.

Для будущих релизов игры: отдельные version/build/sourceCommit в метаданных, сравнение с реально запущенным build, проверка сети без кэша при старте/возврате в меню и по запросу пользователя. Не выдавать ошибку сети за подтверждение актуальности. Использовать согласованные версии или хеши ресурсов; сохранять совместимость локального прогресса.

Новую версию предлагать применить в меню либо после завершения/выхода из матча. Не перезагружать активную игру автоматически, не очищать сохранения ради обновления. Service worker игры ограничивать своим scope и cache prefix; не удалять чужие кэши и не применять принудительную активацию с перезагрузкой активного матча. Офлайн-игру обещать только после отдельной проверки.

Наблюдение на 29.09.2026: опубликованный Crystal Front в src/presentation/browser/main.js проверяет версию по клику на data-version-check. Загружает ./index.html?cache-check=<время> с no-store, извлекает версию из main.js?v=... или HTML, сравнивает с APP_VERSION; при большей версии через 420 мс вызывает location.replace с v и refresh. В этом обработчике нет защиты активного матча. Проверенный удалённый файл содержит APP_VERSION 0.1.32; восстановленная локальная копия проекта старее. Не считать локальную копию источником актуальной публикации.

LPA отдельно читает docs/version.json, сравнивает с последним увиденным значением localStorage и показывает Available/Current. Это не строгая проверка версии исполняемого JS. docs/update-guard.js откладывает запрошенную перезагрузку оболочки, пока overlay открыт; он не перехватывает location.replace внутри игры. Текущие shell service workers не используют skipWaiting/clients.claim; полная смена worker может потребовать закрыть старые окна приложения. Хаб не кэширует сборку игры как часть своей оболочки.

## 7. Обязательная приёмка и передача

Проверить на опубликованной тестовой сборке вместе с реальным хабом:
- Exit из каталога, страницы игры, install-страницы и PWA-ярлыка; возврат на оболочку без автоперезапуска.
- Гость, пользователь, отключённая аналитика, недоступный SDK/сеть.
- Native fullscreen и отказ API; мобильный горизонтальный экран и safe-area.
- Сохранения после закрытия/повторного открытия; нет оставшегося звука и двойных таймеров.
- Двойной Exit, старый launch, неправильные source/origin/protocol, повреждённый payload — без побочных эффектов.
- Прямой запуск без родителя и старая оболочка без config — рабочее главное меню.
- Новая версия обнаружена во время матча — матч не перезагружается; обновление в меню сохраняет прогресс.
- Статистика не дублируется при результате и последующем Exit.

Передать агенту сайта: gameId, URL, commit/build, поддержку player protocol 1, формат сохранений, результаты тестов по средам и ограничения. Физические телефоны/Safari отмечать непроверенными, если тест был лишь в эмуляции. Не объявлять контракт реализованным только по наличию инструкции.
